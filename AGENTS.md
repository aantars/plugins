This repo holds Claude Code plugins, mostly mods (plugins whose behaviour lives in a hooks module, `hooks/register.tsx`). Each plugin is its own folder under a bucket in `plugins/`:

- `productivity/`: daily non-code workflow tools
- `engineering/`: daily code work (none yet; create the folder with the first one)
- `misc/`: kept around but rarely used, not promoted
- `in-progress/`: beta, public on purpose, not listed in the marketplace
- `deprecated/`: no longer used

Only create a bucket folder when its first plugin arrives.

## Plugin folder layout

```
plugins/<bucket>/<name>/
  .claude-plugin/plugin.json   manifest (name, version, description, author, license, "types")
  hooks/hooks.json             { "modules": ["./register.tsx"] }
  hooks/register.tsx           the hooks module
  types/index.d.ts             $.state contract, when the module keeps state
  tests/*.test.tsx             run with `claude plugin test <folder>`
  tsconfig.json                extends ./.claude-plugin/types/tsconfig.json (written by the engine, not committed)
```

`.claude-plugin/types/` is generated by Claude Code when it loads the mod. Never commit it.

## Promoted plugins

`productivity/` and `engineering/` are the **promoted** buckets. Every plugin in them must have:

- an entry in `.claude-plugin/marketplace.json`, with `source` pointing at its folder;
- an entry in the top-level `README.md` and `README.es.md`;
- an entry in its bucket's `README.md`, with a one-line description;
- a docs page in both languages: `docs/<bucket>/<name>.md` (English) and `docs/<bucket>/<name>.es.md` (Spanish), following [.agents/writing-docs.md](./.agents/writing-docs.md).

When you add, rename, or change the behaviour of a promoted plugin, create or re-sync all of the above in the same change.

## Install wording and manifests

Install commands are copied verbatim from [.agents/install-block.md](./.agents/install-block.md). Change them there first, then propagate to both READMEs. Docs pages carry no install commands.

`.claude-plugin/marketplace.json` (marketplace `aantars-plugins`) is the repo's marketplace and lists every promoted plugin. Bump `version` in a plugin's `plugin.json` on every release, or its users get no update. After touching any manifest or hooks module, run from the repo root:

```bash
claude plugin validate .
claude plugin validate plugins/<bucket>/<name>
claude plugin test plugins/<bucket>/<name>
```

and fix every error they report.

## Two languages

Every user-facing doc exists in English and Spanish (Spain) and is kept in sync: `README.md` / `README.es.md`, and every docs page `<name>.md` / `<name>.es.md`. A change to one is applied to the other in the same change. The Spanish version is written as natural Spanish, not a literal translation. Agent-facing files (hooks modules, `AGENTS.md`, `.agents/*`) stay in English only.

## Writing rules

No em-dashes anywhere in this repo (docs, READMEs, code comments). Where a sentence reaches for one, rewrite it with a comma, colon, period, parentheses or a conjunction. Before finishing, search the repo for the em-dash character and remove any.

Write clear, plain, friendly prose. Lead with what the reader gets.
